## 做法（可复现）

`python 小红书小工具/build_minitool.py --silent`，只读 `游戏/`，输出 `dist-silent/` 和 zip：

1. 只拷运行时用到的素材：`data.js` 里的引用，加上代码里**硬写**的路径（`story/stages.js` 的 `war/tent.png`、`office/fg.png`）。
2. PNG → WebP 无损：7.05 MB → 2.45 MB（抽样像素一致）。
3. 图片转 base64 data URI，每约 400 KB 一组写进 `pack/pNN.js`（共 9 个），解决 200 文件限制；`core.js` 的 `G.image` 优先查 `window.PACK`。规范明确允许图片用 data URI。
4. 无声：`data.js` 里 audio / video 置空，引擎本来就对缺失音频做空操作。
5. `touch.js` 去掉全屏（`reqFs = null` 后全屏按钮自动隐藏），去掉 iOS"添加到主屏幕"提示。
6. `rotate_patch.py`：竖屏时 `#rot` 容器 `translateX(fw) rotate(90deg)`；`G.pt` / `G.rect` 把屏幕坐标换成游戏横屏坐标，用在画面点击、方向盘方向、按钮测量上；安全区变量跟着转，游戏左侧多留 24px 躲容器的返回钮。

验证脚本：`sweep_test.py`（按小红书 CSP 起服务，逐章进入，查 404 / 坏图 / CSP 违规，与原版标题画面像素对比，触屏模式）、`csp_smoke.py`、`png_check.py`、`verify_compressed.py`、`measure_budget.py`。

## 走过的弯路和教训

1. **靠读文档猜限制，浪费了很多轮。** 规范里"文件类型表"和"资源加载表"互相矛盾，我花了不少时间推测，还按"保留音频和视频"做了 19 MB 的包。实际上传一次被拒就知道答案。教训：硬限制应该尽早用一个几十 KB 的探针 zip 上传一次摸清（15 秒出结果），文档（尤其旧版）靠不住。
2. **之前那轮压缩（`游戏/dist-compressed`）有三个问题**：PNG 号称无损，实测 2755 张里 1114 张有像素差异，却只省了 0.4 MB；漏了代码里硬写路径的 `bg/war/tent.png`，序章一开场就 404 加坏图报错；仍带 mp3 / mp4，体积 19 MB。教训：判断素材"有没有被引用"不能只看 `data.js`，要同时扫代码里的字面量路径；验证要靠运行时检查（坏图检测），不能只靠静态清单。
3. **我自己的测试脚本连出三个问题，前几轮"失败"其实是脚本的锅**：输出目录没建，后台任务静默失败；Python 自带服务器每个文件一个连接，两千多张图把 Windows 临时端口耗尽（`ERR_ADDRESS_IN_USE`），要用 HTTP/1.1 长连接加大 `request_queue_size`；第一下按 Enter 就已选中"从序章开始"，加上方向键连按每帧只算一次，导致"选章"全进了序章。教训：先确认测试环境本身可靠，再去解读失败。
4. **工具层小坑**：命令里 heredoc 的反斜杠会被吞掉，`\\n` 变成真换行，构建脚本因此语法错误好几次。含转义的补丁用 Write 工具写文件，或用 `chr(92)`。
5. **浏览器插件偶发截图超时或断线**，用 `get_page_text` 兜底；上传文件要用 `file_upload`，不要点文件框。
6. **用量上限打断了两次**，第二次正好卡在旋转版构建完、尚未验证之后。

## 遗留事项

- **没有声音**：音频和视频文件进不了包。可选方案是把音频编码成文本内嵌进 js、用 WebAudio 播放，但这是绕开平台对媒体文件的限制，审核可能不认，没做，需要你决定。
- **版权**：角色是《银魂》同人形象，README 里写明公开发布前要解决授权。标题曲 mp3 已不在包内，但角色形象仍然是。
- **旋转方向和安全区是估计值**：目前把游戏"上边"转到手机右边（手机逆时针转 90°拿，刘海在左），左边多留 24px。真机上不顺手的话改 `rotate_patch.py` 里的方向和边距。
- **旧笔记已过时**：`20261008-151500-小红书媒体体积与限制核对.md` 里"真正的上传上限和格式白名单需要实测"已经被上面的表回答；`游戏/dist-compressed/`（23 MB）有 bug 且不可用，不要再用。
