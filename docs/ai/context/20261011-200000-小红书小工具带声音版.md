# 小红书小工具带声音版（base64 音频 + WebAudio）

日期：2026-10-11

## 结论

- 小工具里**可以有声音**，办法是不把 mp3 当文件放，而是把音频转成 base64 文本写进 `.js`，运行时用 WebAudio 解码播放。2026-10-11 在用户 iPhone 上用探针包实测：音乐和提示音都能听到。
- 平台限制没有变（官方文档 <https://miniapp-sandbox.xiaohongshu.com/minitool/doc> 2026-10-11 重读）：包内文件类型只有 html css js png jpg jpeg gif webp svg woff woff2 json；容器 CSP 不许 `<audio>` 用 data: / blob: 地址（真机上出现过 `media-src 拦截了 blob`）；无网络、无 Worker、无 WebAssembly、无 eval。mp4 / webm 视频仍然进不去（开场动画没有）。
- 兼容基线是 **Android 8.1 出厂 Chrome / WebView 61（ES2017）**，iOS 最低 18.4。

## iPhone 静音拨片

容器里 AudioContext 能运行、解码成功、时钟在走，但**听不到声音**——WebAudio 的输出会被 iPhone 侧边静音拨片吃掉。探针 v2 实测，下面两招同时用就有声音（没有单独测过哪一招够用）：

1. `navigator.audioSession.type = 'playback'`（iOS 16.4+）。
2. 总线 → `ctx.createMediaStreamDestination()` → `new Audio()`，`.srcObject = stream`，`.play()`。没有 URL，所以不受 `media-src` 限制。

解锁要在“手势结束”事件里做（touchend / pointerup / click / keydown 都监听），pointerdown / touchstart 在 iOS 上不算数。`media.play()` 被拒且不是 `NotAllowedError` 时回退直连 `ctx.destination`。

**取舍**：媒体流通道可能给音效加一点延迟。如果真机上打击音效明显滞后，把 `audio_web.js` 里的 `USE_MEDIA_ROUTE` 改成 `false`（只保留 audioSession），再测。

## 做法

- `小红书小工具/web_extras/audio_web.js`：替换 `core.js` 里基于 HTMLAudio 的 `G.audio`，接口一致（`unlock / music / stopMusic / duck / sfx / update`，`el` 用适配对象兼容 main.js 的“补放标题曲”和 touch.js 的“切后台暂停”）。所有素材包（`audio/*.js`）都是 `index.html` 里的**静态** `<script>`，引擎只等包执行完（`APACK` 里出现这个素材）再解码；页面加载 1.5 秒后后台把音效逐个解码好；音乐用到时才解码，缓存上限 48 MB（最近最少使用的先丢）。

> **更正（2026-10-12）**：这份文档和第一版引擎里写过“素材按需动态插入 `<script src>`（同源外链，CSP 允许）”，**这是错的**，当时并没有实测过（探针页用的是静态标签）。另一会话在创作者中心的平台模拟器里实测：页面 load 之后用 `createElement('script')` 运行时插入的 `<script src>` 会加载失败（jojo 点“确认”后报 `loadScript 失败：data/img_bg_common.js`，这是它被驳回的原因；load 之前的静态脚本都能加载）。所以：
> - 第一版的银魂带声音测试包（2026-10-11 部署、之后在审核里显示“审核中 V1.0.1”的那一个）的音频包是动态加载的，**在小红书容器里大概率加载不出来，等于没有声音**（游戏本身不受影响）。
> - 现在的引擎已改成静态包；`build_minitool.py` 加了容器闸门：成品里任何 js 出现 `createElement('script')` 就不出包；`audio_check.py` 加了钩子（load 之后运行时插入脚本一律触发 error 并计数），验证声音照常出、插入次数为 0。
> - 静态包的代价：16 个音频脚本都在首屏同步加载（约 7 MB 文本），启动会比无声版慢一些，真机上没测过耗时。
- `build_minitool.py --audio`：转成单声道 32 kHz mp3（音乐 / 音效默认都是 48 kbps，`--music-kbps=` / `--sfx-kbps=` 可调）→ base64 → `audio/s00.js…`（音效约 700 KB 一包）+ `audio/m_<名字>.js`（每首音乐一包）+ `audio/manifest.js`；`engine/audio_web.js` 紧跟 `core.js`；`touch.js` 里 iOS 的 blob 静音 wav 预热在带声音版里关掉（会被 CSP 拦）。输出 `dist-audio/` 和 `yinhun-minitool-audio.zip`。
- `--release`：去掉左下角的调试状态条（`window.AUDIO_DEBUG`）。**这次上传的测试包带状态条，正式发布前要用 `--release` 重新打包。**
- `--no-title-song`：不带标题曲（`title_song.mp3` 是商业歌曲翻弹，提交审核有版权风险；用户 2026-10-08 决定保留，这个开关留着备用）。
- `--audio-probe`：只在无声版里加一个声音探针（`web_extras/audio_probe.js`，带 A / B / C 三个按钮试不同输出办法）。

## 兼容闸门（新增）

`小红书小工具/es2017_check.js`：用 TypeScript 解析器扫 Chrome 61 解析不了的语法（`?.` `??`、可选 catch 绑定、类字段、正则后行断言……）和 Chrome 61 没有的接口。构建时自动运行，有 [语法] 问题就不出包。

- 第一次运行就抓到 `engine/script.js:174` 的 `G.world.player?.cid`（可选链，Chrome 80）——在 Android 8.1 上整个 `script.js` 解析失败，游戏起不来。构建补丁（`COMPAT`）里改成了 `(G.world.player && G.world.player.cid)`，游戏源码没动。
- **已经发布的 V1.0.0（无声版）也带这个 `?.`**，所以老安卓（Chrome < 80）上可能打不开。下次发布新版本时就会修掉。

## 体积

51 个文件（1 html + 50 js），zip 8.13 MB（上限 10 MB）：图片 WebP 内嵌 2.45 MB + 音频 5.49 MB（92 个：13 首音乐含标题曲、79 个音效）。

## 官方 Skill 1.7.0 的预算与审计（2026-10-11 补充）

另一会话把平台 Skill 1.7.0 解压在 `D:\CodeWorkSpace\jojo-pixel-game\小红书小工具\_skill_1.7.0\unzipped\minitool-zip-builder\`（`references\performance-budget.md`、`js-compatibility.md`、`css-compatibility.md`、`cross-platform-h5.md`，以及官方审计脚本 `scripts\audit_artifact.py`）。

- 官方审计跑在 `yinhun-minitool-audio.zip` 上：**PASS，2 条 WARN**——zip 7.75 MiB（建议 ≤ 2 MiB）、文本合计 11.44 MiB（> 5 MiB 提示）。已上架的无声版同样有 1 条 WARN（zip 2.58 MiB），所以警告不是拦截项，但提交审核时是否被判风险，没有证据。
- 官方规则：单条 Base64 解码后 > 100 KiB 提示风险，> 1 MiB 视为大 Base64、应改独立包内文件。我们没有别的路（mp3 文件类型不被接受），所以音频只能 base64；其中**只有标题曲超过 1 MiB**（48 kbps = 1.07 MiB），所以构建里标题曲单独降到 40 kbps（≈ 0.89 MiB，`--title-kbps=` 可调）。13 条 > 100 KiB 是提示级别。**这次上传的测试包还是旧参数（标题曲 1.07 MiB），下次打包（`--release`）会带上新的。**
- 官方文档里还有一句“不要通过改后缀或运行时解压字符串来隐藏大数据”——这针对的是规避体积检查；我们的做法是把平台不收的媒体文件换成 js 内嵌，审核是否认可没有证据，仍然是主要风险。
- `cross-platform-h5.md`：PC 模拟器不产生真实 `env()`，要注入 `--safe-area-inset-*` 变量，写成 `var(--safe-area-inset-*, env(...))`；jojo 已在它的 `rotate_patch.py` 里做了，银魂尚未同步。
- 另一会话查出 jojo 上次被驳回的原因是 Chrome 61 兼容（`Object.fromEntries`、`??`、`Promise.finally`）加按钮无语义；它们的 `polyfill.js` / `compile_chrome61.js`（esbuild + acorn 转译到 chrome61）在 jojo 的 `小红书小工具\` 下，可复用。银魂用 `es2017_check.js` 扫过，只有 `script.js:174` 的 `?.` 一处，已修；接口类（`Object.fromEntries` 等）没有命中。

## 银魂 V1.0.1 被驳回：疑似“模拟器里没旋转、没按键”（2026-10-12）

银魂带声音测试版（V1.0.1）被驳回，理由仍是“小工具功能缺陷，可能是页面按钮无法点击”。用户判断原因是**游戏没有顺时针旋转 90°**。在平台模拟器（表单右侧手机预览，其实是桌面 Chrome 的 iframe，`miniapp-sandbox.xiaohongshu.com/simulator/...`）里实测佐证：

- 旧测试包在模拟器里是一个**没旋转的小横屏**（约 170 px 宽）、**没有屏幕按键**。原因是之前给公网版加的“电脑适配”：`G.touchDev`（手机 / 触屏识别）为假就不旋转、不弹手机按键，而模拟器是桌面 UA，被当成电脑。已上架的 V1.0.0 是在这个改动之前打的，竖屏一律旋转，所以通过了。
- 修复（`rotate_patch.py` 的 `_core_helpers`）：小红书版里 `G.touchDev = true`（容器永远是手机竖屏，包括审核模拟器），竖屏一律**顺时针转 90°**（`rotDir = 1`），屏幕按键常显；公网版仍保留电脑 / 手机识别。
- 验证：桌面 Chrome（无触屏、320×693）+ 小红书 CSP，`touchDev=true / rot=true / #rot = translateX(320px) rotate(90deg) / 按键可见`，鼠标点“确认”从标题进到序章，无页面错误（`scratchpad/emu_check.py`）；平台模拟器里满屏旋转、有方向盘和 J / E 按钮，点“确认”进入序章章节标题卡。
- 另一条独立的 bug 也在这一轮发现并修了：音频包不能运行时动态插入（见上面的更正）。银魂 V1.0.1 被驳回时音频包是动态插入的、被引擎吞掉了错误，不会卡住游戏，所以那一条不足以解释驳回——旋转 / 按键更像主因，但**没有平台给出的证据**，只是和 jojo 一样“模拟器里看不到能点的按钮”。
- 同类线索：锈湖 V1.0.2 的规则是“手机按横屏设计，竖屏显示旋转提示”，在竖屏的桌面模拟器里可能也是只有提示、没有可操作画面；还没在模拟器里确认。

## 验证

- 本地（小红书同款 CSP、手机竖屏触屏，`audio_check.py`）：标题曲在播（总线 RMS 约 0.11）、`punch_big` 音效从 0 升到 0.49、换 `battle` / `yorozuya` 正常；无 CSP 违规 / 404 / 页面报错。
- `sweep_test.py` 15 章逐个进入：全部通过，序章 / 第一章 / 第七章音乐分别是 prologue / yorozuya / tension。
- 平台部署：显示“部署成功”（未提交审核）。
- **没验证**：带声音版在真机上是否听得到、音效是否滞后（只有用户的 iPhone 能验证）；Android 真机；审核会不会因为 base64 音频或标题曲不通过。
