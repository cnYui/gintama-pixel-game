## 三、角色图集

### 银魂（我做的）

- 脚本：`D:\大疆\游戏素材\银魂\烘焙脚本\bake_characters.py`（约 1 分钟，4 进程）。
- 做法：
  - 每个角色、每个动作都用原引擎的 `chars.render_sprite()` 按 12 fps 逐帧渲染；
  - **循环动作**找最小周期：首尾像素完全相同就 `seamless: true`；找不到就取首尾差异最小、又尽量短的帧数，标 `"approx"` 并记差异像素数；
  - **一次性动作**（出拳、挥刀、受击……由进度 p 驱动）p 从 0 到 1 采样 8 帧；
  - 帧完全相同的动作记成别名（`aliases`），不重复存；
  - 统一格子：以脚点为基准取全部帧的最大外接范围 + 1 px 边，`pivot` = 脚点；
  - 头像：每个表情的头 + 对话头像；
  - 变体：路人 4 种配色（`townsman__v1..3`、`townswoman__v1..3`）、新八系围裙（`shinpachi__apron`，第二章用）。
- 结果：**49 个图集（42 个角色 + 7 个变体），13412 帧**；`验证图集.py` 0 问题；`查看器.html` 双击能浏览全部角色和动作。
- 踩到的坑：
  - 取样窗口夹到了下一次眨眼（每 3.1 秒眨一次），把完全循环误判成近似，改成只取前 33 帧；
  - `int((t*720) % 360)` 在 `t = k/12` 上有浮点误差，取样时间加 1e-6；
  - 跑步在 12 fps 下不可能完全首尾衔接，按“差异 ≤ max(15 px, 2 倍最小差异) 里最短”的规则取帧数。

## 六、网页游戏（序章 + 第一章）

### 玩法和数值

- 操作：方向键 / WASD 移动（含前后纵深）；Enter / 空格 / E 对话、调查；J 三连击（下劈 8、上撩 8、突刺 14 并击退）；K 跳（空中 J 跳斩 10）；按住 L 防御（挡正面）；Esc 暂停。
- 玩家 100 血，每场战斗开始回满；被打后 0.55 秒无敌。敌人杂兵 22–28 血（敌人出手：斩 9、拳 7）；Boss 120–140 血、体型 1.4–1.45 倍、会重击（16）和冲锋（闪红光、头顶“!!”）。敌人出手前头顶“!”预警 0.32–0.5 秒，同时最多两个出手。被打飞的敌人飞上天变成星星。
- 输了弹“银时倒下了…… / 再来一次 / 回到标题”，从这场战斗开头重来。

### 设计要点

- **按键名字就是游戏提示里的键名**（J K L E）：“按 J 停下转轮”“按住 L 防御”在手机上不用改词。
- **按场景收起**：对话 / 旁白 / 过场 → 只留暂停（点屏幕继续，按钮不挡字）；连按 / 看准时机 → 只留 J；菜单 / 选项 → 方向盘 + J / E；自由走动 → J、L 暗着；战斗 → 全亮。藏起来的按钮 `pointer-events: none`，手指直接穿过去点到画面。
- **点画面 = 确认**（原来的鼠标点击行为），菜单里改成“点中哪项选哪项”，点菜单外 = 取消（有取消项时）。
- **`G.touch.safe`** 记着按键压到了游戏画面的哪里（宽屏手机的黑边够放按键时就是没压）；以后新增贴边的 UI 用它躲开。
- **手离开屏幕 2.5 秒按键淡到 34%**，一碰就回来（16:9 的手机上方向盘会压住画面左下角的角色，这是这样做的原因）。
- 触屏判定：`(pointer: coarse)` 或手机 UA；`?touch=1 / ?touch=0` 强制；接实体键盘按一下键就收起、再碰屏幕又出来。

### 这次的坑 / 要记住的

| 问题 | 原因 | 处理 |
|---|---|---|
| 序章点“开始”后 `G.scene.name` 不是 `world` | 序章一开始放开场动画（`video` 场景） | 测试里判断“不是 title”就行 |
| 手机上第一下触摸标题曲没出声 | 原来 `pointerdown` + `{ once: true }` 补放；Chrome 里**触屏的“用户激活”是手指抬起（pointerup / touchend / click）才算**，pointerdown 不算，补放被拒了又不再试 | `kick` 改成 5 种事件都听、放出声为止才取消；全屏钮用 `click`（同理） |
| iPhone / iPad 的 Audio 元素每个都要在手势里先放一次 | WebKit 的规则；游戏每换一首音乐 `new Audio`、音效池也是按需建 | `touch.js` 的 `primeAudio`：第一次抬手时给 79 个音效各建一个元素静音点播；音乐改用两个提前点过的元素轮流放（点播成功才替换 `G.audio.music`，没成功就保持原样）。**没在真机上测过**；iOS 的 `volume` 只读，音乐音量调不了、淡入淡出无效 |
| 提示框（`S.hint`）在下面，被方向盘和按钮盖住 | 手机上下面两边是按键 | 手机上提示放顶（血条、同伴条下面），宽度躲开右上钮；其余地方不变 |
| 首次提示条弹在载入画面上，没人看见 | 触屏一判定就弹 | 等 `G.scene` 有了（标题出来）再弹，位置在上面（下面会盖住菜单项） |
| 修改 `main.js` / `touch.js` 里的中文字符串后字库缺字 | 字库只收 `story/*.js`、`engine/*.js`、`main.js` 里引号内出现过的字 | 重跑 `python tools\build_assets.py font data`（只有 font 一节变了，其余几节 diff 过没变） |
| Python 自带 `http.server` 不支持 Range | iPhone 的 Safari 放视频 / 音频要分段请求 | `serve_phone.py` 自己补了 206 / 416 |
| 后台一次性跑 `( … ) &` 会被工具杀掉 | 外层命令一结束子 shell 就没了 | 直接 `run_in_background` 整条命令，里面用 `;` 串起来 |

### 没做 / 没法测

- **真机没测过**（我只有 Chromium 的触屏模拟：dpr 3、`has_touch`、CDP 多指）。手感（按钮大小、位置、方向盘死区）要用户上手后再调；常调的三处：`index.html` 的 `.tc-j / .tc-k / .tc-l / .tc-e` 的 `--x / --y / --s`、`touch.js` 里 `layout()` 的大小公式、`padMove` 里的死区（0.3）和角度（60°）。
- iOS 声音按规则写的，没真机验证；iPhone 没有网页全屏，只能“添加到主屏幕”。
- 没做手柄（Gamepad API）、没做左手模式、没做按键位置自定义。
- 公开发布前：标题曲是商业歌曲翻弹、角色是同人形象（见 README「注意」）；`手机试玩.bat` 只在局域网里用，不会把游戏放到公网。
