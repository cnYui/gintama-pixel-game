# 银魂 剧情分镜（日后按分镜做游戏关卡）

故事按时间顺序切成 **15 个场景**，全片 5:34.2。每个场景 = 一个故事段落，也是日后游戏里的一关 / 一章。分镜有四层，由粗到细：

| 层 | 在哪 | 内容 |
|---|---|---|
| 1. 总表 | `分镜总表.md` | 15 个场景一张表：标题、成片时间、时长、音乐、出场角色、台词数、音效数 |
| 2. 故事分镜（设计意图） | `场景分镜\sNN_*.md` 的第一节，原文在 `CONTRACT_原文.md` 第 8 节 | 主会话在启动工作流前写的分镜：每个场景发生什么、谁登场、哪句台词、几秒长、用哪首音乐 |
| 3. 镜头表（实际实现） | `场景分镜\sNN_*.md` 的“镜头表”节 | 每个场景代理写在场景文件开头的 SHOT LIST：逐镜头的起止秒、景别 / 镜头运动（zoom、平移）、角色动作、特效、台词和音效的触发时刻（如“13.62 IMPACT FRAME”） |
| 4. 机器可读 | `storyboard.json` | 上面全部 + 台词时间表（`subs`）、音效 cue（`sfx_cues`）、音乐切换（`music`）、出场角色、用到的背景函数 |
| 5. 分镜图 | `分镜图\sNN_*.png` | 每个场景一张联系表：每 0.5 秒一帧（引擎真的渲染出来的，含字幕和淡入淡出），带时间标签；一眼看完这个场景的镜头顺序 |

另有 `设计过程\`：主会话的可读版、写过的 CONTRACT.md（首版）、工作流脚本（怎么把故事拆给 41 个代理）、41 个子代理的任务书和最终报告。原始 jsonl 在 `..\会话备份\`。

`export_storyboard.py` 能从源码重新导出 1、3、4 层（`python export_storyboard.py`，不渲染视频）；`export_contact_sheets.py` 重新导出分镜图（约 12 秒）。

## 用分镜做关卡时的几个提醒

- 时间都是**场景内秒数**（每个场景从 0 起算）；全片时间 = 前面场景时长累加（总表里有）。
- 每个场景是“时间的纯函数”（原工程的设计）：同一时刻画面相同、没有状态。做游戏时把“时间 t”换成“玩家输入 + 游戏状态”，镜头表里的镜头运动（zoom、平移）和特效（冲击帧、速度线、屏幕抖动）可以照着抄。
- 角色名牌（`name_card`）、篇章卡（`chapter_card`）、台词框（JRPG 风，带头像和打字音）是原工程的字幕系统，在 `源码\engine\text.py`；图集里没有，需要的话照着重做或直接复用源码渲染。
- 台词都是中文，写在每个场景的 `subs` 里（说话者 id、起止秒、文字）。
- 场景代理在报告里记下的问题（共享文件里的毛病）在 `设计过程\子代理\` 里。
